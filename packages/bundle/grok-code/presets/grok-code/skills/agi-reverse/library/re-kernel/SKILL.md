# Kernel reversing (cross-platform)

<CORE RULE>
**The hard part of kernel-mode analysis is not "which tool to decompile with", but "what to suspect first when an observation conflicts with the expectation".**
The platforms differ in shape (PE / ET_REL / Mach-O / a module collection), but they share this: **the build and load model decides what you can see** — version, how symbols are resolved, structure randomization, signature, load stage, and the cached collection all make two things that "look the same" actually different.
So the order is always: **confirm first that "the copy I am looking at is the one that is running / being loaded", then talk about the logic.**
</CORE RULE>

## Platform differences (not synonyms)

| Platform | Unit shape | Load and signature model | Where type information comes from | Main observation surface |
|---|---|---|---|---|
| Windows | **split the driver model first**: WDM / KMDF / UMDF / minifilter / NDIS·miniport; only then talk about `.sys` (PE) | SCM registration + driver signing (WHCP / test signing; **from 2026-04, legacy cross-sign is not trusted by default**) | PDB (public≠private), WDK / `ntddk.h` types | WinDbg kernel debugging, `!drvobj`/`!process`/`!wdfkd.*`, Volatility |
| Linux | `.ko` (**ET_REL** relocatable object) | `insmod`/modprobe + vermagic / symbol CRC / signature trailer | BTF (including split BTF and `.BTF.base`), vmlinux, source | `/proc/kallsyms`, `/sys/module/*/sections/`, kprobe/ftrace, memory cross-view |
| macOS | **three models**: KEXT (kernel mode) / DEXT·DriverKit (**user mode**) / System Extension (framework) | AuxKC (loaded at boot) + UAKL + Reduced Security / System Extension activation approval | symbols, Mach-O, `Info.plist` (IOKitPersonalities) | IORegistry, `kmutil`, dSYM+KDK; a dext is analyzed and debugged in user mode |
| Android | GKI module / vendor module | GKI signature + **KMI symbol allowlist** | BTF, KMI symbol list, `Module.symvers` | the partition the module lives on, the `modules.load` plan |
| seL4 (microkernel) | **capability system**: objects (TCB/Endpoint/CNode/Frame/Untyped/SC) + cap distribution | **no capability means no access right**; objects are created at construction time by the spec/loader | capDL spec (`.cdl`), CAmkES ADL, ELF | capDL snapshot (`seL4_DebugSnapshot`), `seL4_DebugCapIdentify`, QEMU emulation |
| **Fuchsia/Zircon** | **a handle references a kernel object** (the integer is **process-local**) + a **user-mode driver component** (DFv2) | driver manager maintains the node topology, driver index matches by **bind rules**, driver host hosts the instance | FIDL, component manifest, bind rules | driver manager/driver index match and topology, driver-host process partition, the handle+rights relationship graph |
| **FreeBSD** | `.ko` (KLD, relocatable ELF) | **linker sets + `SYSINIT`** (`SI_SUB_*` + `SI_ORDER_*` ordering) + the runtime kernel linker | symbols, `set_*` collections, source | `__start_set_*`/`__stop_set_*` bounds, the load path (built-in/preloaded/`kldload`) |
| **illumos/Solaris** | `.so` kernel module (DDI/DKI driver) | `_init` → `mod_install(&modlinkage)`; `_fini` → `mod_remove` | the `modlinkage`→`modldrv`→`dev_ops`→`cb_ops` static chain | read `dev_ops`/`cb_ops` field by field (including the `nulldev`/`nodev` placeholder semantics) |
| **OpenBSD** | the same shape as ordinary Unix, but the kernel **is randomly relinked on every boot** (KARL) + autoconf runtime matching | link kit + rc background relink; detach may wait for users to exit | symbols (**after KARL, compare by symbol, not by byte**) | link kit/rc relink traces, autoconf tables, pledge/unveil state |
| **NetBSD** | `.kmod` (ELF, resolved by the kernel linker) | **on-demand autoload** (including recursive dependencies) + automatic unload; a strong version constraint between module and kernel | the module version report and the kernel version | the actual module path (the layout changes with `KERNEL_DIR`), `.plist` properties |
| **Genode** | **component tree**: session + capability + quota | parent-mediated routing; names are **remapped level by level** | the component's XML configuration and route table | PD-local naming of a capability, the quota donation chain, ROM update |
| **MINIX 3** | **user-mode services + RS self-healing restart** | RS monitors/restarts; the label is stable, **the endpoint changes** | fixed-length message (56 bytes) definitions and grants | service label↔endpoint, grant checks, the live-update phase |
| **Plan 9 / 9front** | **a per-process namespace + a user-mode file server** | bind/mount/union; a service is published through `/srv` and then mounted | 9P fid/qid/walk and message types | namespace bind history, 9P session alignment |
| **HelenOS** | a user-mode server + a **fibril** (the kernel does not know) | user-mode DDF; devman scores by match id and starts the driver | DDF structures (`driver_ops_t`) | distinguishing a kernel thread from a user fibril |
| **Redox** | **scheme + a user-mode daemon** | the kernel turns a file operation into an SQE/CQE message | SQE/CQE fields, handle mapping | scheme name → provider; the mapping of the client fd to the provider descriptor |
| **Haiku** | a kernel module, but split into two layers, **driver module / device module** | the Device Manager's device_node tree + **on-demand discovery** | node attributes and bus-type rules | `/dev` path ↔ node ↔ driver |
| **IBM z/OS** | **TCB and SRB**, two kinds of schedulable unit | cross-memory / PC / AR mode | the address-space triple (home/primary/secondary) | the current primary/secondary/home and the work-unit type |
| **IBM i** | object-style (a library is itself a container object) | **single-level store**: memory and disk are the same 64-bit address space | an object's qualified name and a global pointer | an object reference vs a main-storage address |
| **OpenVMS** | process/thread + **AST asynchronous control flow** | `$QIO` + an event flag + an AST | IOSB, AST parameters | the completion flow (IOSB → flag → AST) |
| **Unikraft / MirageOS** | **library OS / unikernel**: the application and the OS libraries are linked as a whole | the build target decides everything (native vs binary; unix/hvt/xen…) | the build configuration and the shim | how a call enters the "kernel", and where the device wiring comes from |
| **HIC** | **same-privilege processes + MMU isolation** (Privileged-1 and Core-0 share a physical privilege level); a driver maps only the MMIO/shared memory it was authorized for | a self-describing module (UUID/version/endpoints/resources/dependencies/signature) + capability accounting; dynamic load and rolling update | module metadata, the capability table | the domain / capability / mapping / device ownership / version / lifecycle topology |

## Failure-mode decision table (the main entry of this skill)

**When a decompilation result or a runtime observation conflicts with the expectation, suspect from this table first, then rule things out**:

| Symptom | Suspect first (in order) | Direction |
|---|---|---|
| every struct offset is wrong | ① does the BTF match the target ② does the kernel build match ③ **RANDSTRUCT** (`CONFIG_GCC_PLUGIN_RANDSTRUCT`; this kind of kernel carries taint `T`) | priority: target BTF > exact-build debug info > exact seed+config > dynamic verification > guessing an offset (worst) |
| symbol resolution looks weird | ① **MODVERSIONS** (CRC) ② **Android KMI** ③ **livepatch** (`.klp.rela`/`.klp.sym`) ④ split BTF | check each against its branch; do not call it "file corruption" |
| the file and the runtime behavior disagree | ① Linux runtime relocation / the init-only section is already gone ② **the macOS AuxKC is still running the old version** ③ Android actually loaded a same-named module from another partition | record "disk version / running version / boot time"; do not look only at the disk |
| disk code and memory instructions disagree | **rule out legal dynamic patching first**: alternatives, static keys/jump labels, ftrace, livepatch, paravirt, kprobe (Linux) | only an "unexplained modification" raises the rootkit suspicion — a lot of things that "look tampered with" are actually kernel mechanisms |
| some function cannot be found in memory | ① the `__init` section was released ② built-in (there was never a separate .ko) ③ stripped ④ split BTF | follow "**what state change init left behind**" (callback/hook/a patched pointer), not the init itself |
| `kallsyms` is all 0 / addresses do not match vmlinux | ① `kernel.kptr_restrict` ② **KASLR** (both kernel text and the module base are randomized) | look at the policy and recover the slide first; do not judge "hooked" or "not the same kernel" |
| a symbolicated offset keeps drifting / resolves to a string | ① **`__TEXT_EXEC.vmaddr`** was missed (an arm64e KEXT panic base has to add it) ② the symbol file and the panic image disagree on **UUID/build** | adjust the base by segment first, then check UUID+arch+exact build (KDK); do not suspect the disassembly |
| the kext signature is legal but it still will not load | it is not only the signature: **UAKL / user approval / Reduced Security / AuxKC rebuild + reboot**; an x86_64 kext also hits `KMErrorDomain 71` (**Rosetta does not translate a kext**) | judge architecture / signature / approval / UAKL / boot policy / AuxKC inclusion separately |
| UserClient will not connect / `kIOReturnBadArgument` | ① activated/entitlement/Team ID/sandbox ② **the dispatch count/size/completion rejects before the handler** | order it "authorization chain first, then ABI, then the handler"; do not guess selector logic first |
| a module "disappeared" | ① built-in (there was never a module file) ② **a rootkit unlinked it** (module list unlink) ③ a macOS Kernel Collection ④ Android, another partition or another boot stage | cross-check with a cross-view; do not conclude from a single view |
| driver IPC cannot be called | ① selector/ABI ② **entitlement** ③ sandbox ④ Team ID (macOS) ⑤ the service was never activated ⑥ **the dispatch count/size/completion rejects before the handler** (the Windows case isomorphic to `kIOReturnBadArgument` is in the macOS branch) | order it from "can it connect" to "how it is called after it connects", rather than guessing the selector directly |
| the IRP handler cannot be found / `MajorFunction` is empty | **decide the driver model first**: KMDF (`!drvobj` pointing at Wdf01000.sys is normal), NDIS/miniport, minifilter, UMDF | go find the matching **callback-registration graph** (Evt* / Ndis* / FLT_* / WDF config dataflow), not "there is no I/O" |
| `IoCallDriver` has returned but the behavior is not finished | **completion edge**: `STATUS_PENDING` is not a failure; the final state is in `IRP->IoStatus.Status` and the completion path (`STATUS_MORE_PROCESSING_REQUIRED` takes over) | the CFG has to add the completion edge, or cleanup/copy-back/retry looks like "nobody calls it" |
| an old `.sys` suddenly will not load (the signature looks fine) | ① **from 2026-04, legacy cross-sign is not trusted by default** (only WHCP is accepted; evaluation mode comes first) ② under HVCI, Test Mode still requires a signature ③ Secure Boot blocks testsigning | do not judge "the signature is corrupt" or "the API changed"; check the policy layer first (see [[windows-kernel]] §26–28) |
| an abnormal ELF section is seen | ① a signature trailer (appended at the end of the ELF) ② livepatch `.klp.rela` ③ BTF/`.BTF.base` ④ ORC unwind ⑤ architecture/toolchain metadata | classify first, then handle it; **do not truncate/strip in order to "fix" it** |
| the same CPtr integer is treated as the same object | **a CPtr is a local address in each CSpace**, not a global id (seL4) | recover each CSpace mapping first, and align by **kernel object** |
| a thread/service is "stuck" or looks like "the configuration is corrupt" | ① MCS: the SC is not bound / the budget is exhausted / a passive server has no SC to begin with ② the fault handler did not fix the fault | check it by MCS semantics (SC / budget / the donation chain); **do not apply a POSIX deadlock** |
| an IRQ arrives only once | there is no Ack (seL4: without an ack the kernel does not deliver later interrupts) | check `seL4_IRQHandler_Ack` inside the IRQ handling loop |
| the same handle integer is treated as the same object | **a handle integer means something only inside the current process**, and it can be reused after close (Fuchsia/Zircon) | recover each process's handle table back to alignment on the **kernel object**; the relationship graph records the triple **object + handle + rights** |
| a handle that was held now reports `BAD_HANDLE` | **it was sent away by `channel_write`** (in-transit / transfer), or a failed write discarded it | check the transfer semantics first (including whether `ZX_RIGHT_TRANSFER` was removed); **do not judge a UAF** |
| there is clearly inter-driver IPC but the syscall trace has no channel call | **the two drivers co-locate in the same driver host** → driver runtime's in-process channel | verify with the driver-host partition (node symbols go in-process only when they co-locate); do not judge "the call was hidden" ([[zircon-kernel]]) |
| driver binding cannot be found by `bus probe()` | DFv2 matches **node properties + bind rules through the driver index** | recover the chain node → bind rules → driver component → driver host, rather than looking for a probe callback ([[zircon-kernel]]) |
| some init / registration function **has no caller at all** | **linker-set registration** (FreeBSD `SYSINIT`; for Zephyr see [[re-rtos/zephyr]]) | walk back from the function address to the registration structure and the `set_*` collection it belongs to; **do not mark it dead code** ([[freebsd-kernel]]) |
| a long run of contiguous pointers/objects, section name `set_*` | the kernel's own **linker set** collection | explain it as a registration collection, not as a jump table / obfuscation table |
| judgments of "what the driver supports" disagree | `nulldev` (a legal no-op) and `nodev` (unsupported, returns `ENXIO`) were mixed up | read the placeholder semantics of `dev_ops`/`cb_ops` field by field ([[illumos-kernel]]) |
| the same kernel version **has a different layout on every boot** / two binaries disagree byte for byte | **KARL relink** (OpenBSD) — it was not patched, and the versions do not differ | compare by symbol/semantics; do not do a byte comparison ([[openbsd-kernel]]) |
| a module **appears by itself / disappears by itself**, and no loader can be found | the kernel **autoloads on demand** and unloads automatically (NetBSD) | align it to the event that triggered it and the `.plist` setting; look at the timeline, not the process ([[netbsd-kernel]]) |
| module load failed but the file looks fine | module-to-kernel **version compatibility** (NetBSD) | check the exact kernel version/build first; do not force-load casually ([[netbsd-kernel]]) |
| the same service name looks like it connected to a different object / a capability integer is treated as a global id | a name is valid only at the **local level**, and a capability is a **PD-local name** (Genode) | align by the route table + the label chain / by session ([[genode]]) |
| a driver process **disappears and reappears** | **RS self-healing restart** (MINIX 3) — it is not persistence | align the label (stable) with the endpoint (it changes) ([[minix3]]) |
| an integer in IPC is treated as a buffer pointer | it may be a **grant ID** (MINIX 3; messages are a fixed 56 bytes) | recover it as `(endpoint, grant ID, offset, rights)`; `EPERM` means the grant is invalid, not that privilege is insufficient |
| the same path reaches a different object | **a per-process namespace** (Plan 9) | recover the bind/mount history and the 9P session; do not assert the same resource from the path ([[plan9]]) |
| a lot of "thread switches" appear inside one OS thread | a **fibril**: user-mode cooperative scheduling, and **the kernel does not know about it** (HelenOS) | do not look for the evidence in kernel scheduling ([[helenos]]) |
| what `read`/`write` lands on is not a filesystem | **the scheme decides the meaning** (Redox) | find the provider by scheme name; the client fd and the provider descriptor are not equal ([[redox]]) |
| the driver is not there at boot, and appears later | **on-demand discovery** (Haiku) | check the bus-type rules and the on-demand flag; do not judge a load failure ([[haiku]]) |
| the execution address belongs to another address space | **a cross-memory / PC instruction** (z/OS) | distinguish home/primary/secondary and TCB/SRB; do not judge a hijack ([[zos]]) |
| a routine has no caller but has behavior | **AST asynchronous control flow** (OpenVMS) | add the AST edge; a wait that "returns and then waits again" is normal ([[openvms]]) |
| an object address does not look like a DRAM pointer | **single-level store** (IBM i) | memory and disk are the same 64-bit address space; do not apply the POSIX file model ([[ibmi]]) |
| the user → syscall → kernel boundary cannot be found | **a library OS / unikernel** | decide the build target first; a "system call" may be only a function call ([[unikraft-mirageos]]) |
| a module carries self-describing metadata of UUID/version/endpoints/resources/dependencies/signature | **do metadata triage first, then disassemble** | the metadata is the first layer of evidence ([[hic]]) |
| a fast-path IPC looks like "entry page → bitmap test → failure branch → jump to the business page", and the jump can trigger a fault | a **normal IPC boundary** (the page-switch / verification path in isolation mode) | do not judge obfuscation / a CFI stub / a broken CFG ([[hic]]) |
| the same capability structure has a different layout across versions or documents | **do a generation fingerprint first** (per-core with no global lock ↔ a protected global table) | do not apply a structure directly from the latest document ([[hic]]) |
| init has a lot of reset / state probes that "look redundant" | a **sandbox restart / recovery path** (rebuilding the driver ≠ the hardware returned to a clean boot) | do not delete it as boilerplate ([[hic]]) |

## Procedure (the cross-platform main line)

1. **Confirm identity**: which copy this is (the version on disk / running / in the loaded collection), which build (vermagic / CRC / KMI / signature), which shape (PE / ET_REL / Mach-O / a user-mode dext)
2. **Types and symbols**: official type sources first (PDB / BTF / the symbol table / the KMI list), then exact build information, and inference last
3. **Functional skeleton**: split function from imports/exports and the kernel-API call relationships — this step is especially effective when the target is closed-source or stripped
4. **Hooks and hiding**: enumerate hook landing sites (a table slot / inline text / a callback array / an operation structure) + a **cross-view cross-check** (the user-mode view vs the kernel's real objects and memory)
5. **Verify and close**: check at runtime (debugger / kprobe / IORegistry / the memory side), and file the conclusion and the evidence per [[re-analyze/analysis-contract]]

## Platform branches (references)

- [[windows-kernel]] — **split the driver model first** (WDM/KMDF/UMDF/minifilter/NDIS·miniport); `GsDriverEntry` is not the business entry; the WDM `DRIVER_OBJECT` assignment graph; KMDF Evt* callbacks and `WDF_*_CONFIG` dataflow (`!drvobj` pointing at Wdf01000.sys is normal); miniport/NDIS registration callbacks; **the device stack and the INF stack position**; a minifilter's altitude and the pre/post pipeline; buffer semantics of `CTL_CODE` and `METHOD_*` (NEITHER user pointers); **the completion edge and `STATUS_PENDING`**; IRQL semantics of a `PAGE` section; Driver Verifier fault injection and 0xC9; PE relocation; PDB public/private and signature+age; `!analyze -v` is only an entry; **UMDF/Wudfhost and `!wdfkd.wdfumdevstacks`**; **the 2026 driver-signing policy and HVCI compatibility requirements**; the callback-registration graph
- [[linux-kernel]] — **three don'ts** (a .ko is not an ordinary ELF / disk code is not runtime truth / after suspecting a rootkit, do not trust a single enumeration); artifact identification (a bzImage is a compressed boot image); relocation first and `.modinfo`; the full set of legal `.ko` shapes (signature trailer / compression / BTF and split BTF+`.BTF.base` / RANDSTRUCT / livepatch `.klp.*` / ORC unwind); **the legal dynamic-patching list** (alternatives/static keys/ftrace/livepatch/paravirt/kprobe); the `__ex_table` exception edge; ENDBR; the callback-registration graph; `__init` release and load-stage diagnosis (`CONFIG_MODULE_STATS`); the two MODVERSIONS format generations; KASLR and kptr_restrict; rootkit cross-view
- [[macos-kernel]] — **three models mixed** (KEXT kernel mode / DEXT user mode / System Extension framework); `Info.plist` first and the IOKit class graph (OSMetaClass/vtable); a codeless kext; **disk vs AuxKC version** and the unload illusion; arm64e PAC pointers; `newUserClient`→`externalMethod` and the dispatch `check*` fields (`kIOReturnBadArgument` may be the framework refusing); the authorization-chain troubleshooting order; a dext is analyzed and debugged in user mode; Kernel Collection; **the `__TEXT_EXEC` offset of panic symbolication and UUID/KDK matching**; UAKL/Reduced Security/AuxKC and **KIP**; the era difference of rootkits; two-machine debugging for a KEXT vs same-machine debugging for a DEXT
- [[android-kernel]] — GKI vs vendor module, protected symbols and the KMI allowlist, KMI branches are not interchangeable, module location and the load plan
- [[sel4-kernel]] — **the capability system**: a CPtr is a local address, not a global id; capDL/CAmkES semantics; badge and rights; CSpace guard/depth; an error code is a diagnosis; Untyped and device untyped; IRQ and the DMA bypass of a user-mode driver; fault IPC; MCS (SC/budget/passive server/reply object); capDL snapshot cross-view
- [[zircon-kernel]] — **handle locality** (the integer is valid only inside the process, it can be reused after close, and cross-process comparison is meaningless), **in-transit and transfer** (a write removes it from the sender, a failure also consumes it, `ZX_RIGHT_TRANSFER`, rights can only be narrowed; the relationship graph records object + handle + rights), **DFv2** (driver manager / driver host / driver index / driver runtime; bind-rules matching rather than `bus probe()`), **the local channel of co-located drivers** (there is IPC but no syscall), `/dev/foo` is a FIDL channel rather than a Unix device file
- [[freebsd-kernel]] — **linker sets and `SYSINIT`**: registration entries go into the startup/shutdown collection, ordered by `SI_SUB_*` + `SI_ORDER_*` (the same sub and the same order have an undefined order), **modern ELF is bounded by `__start_set_*`/`__stop_set_*` and is no longer NULL-terminated** (scanning the old structure walks off the end), the general test for a `set_*` collection, the merge timing of a KLD's `SI_SUB_KLD` and the reverse teardown
- [[illumos-kernel]] — **the DDI/DKI driver skeleton**: `_init`/`_fini`/`_info` → `modlinkage` → `modldrv` → `dev_ops` → `cb_ops`; **`nulldev` (a legal no-op) vs `nodev` (unsupported, returns `ENXIO`)**; `attach`'s `DDI_ATTACH`/`DDI_RESUME` (`DDI_PM_RESUME` is obsolete); per-instance init belongs in `attach()`; `_fini` must not free resources when `mod_remove` fails
- [[openbsd-kernel]] — **KARL relink** (the `.o` files are randomly relinked on every boot; **what changes is the internal layout, not the load base**, which differs from KASLR; a byte-for-byte difference cannot be judged a patch); **autoconf** runtime match/attach (`foo_attach` with no caller is normal, and detach may wait for users); the one-way ratchet of **pledge/unveil** and an uncatchable SIGABRT ("it can access at startup, then suddenly cannot" is the design pattern; do not attribute it to an external intercept)
- [[netbsd-kernel]] — **on-demand module autoload** (it appears even with no modload, including recursive dependencies) and **automatic unload**; **a strong compatibility constraint between module and kernel** (a mismatch fails, and a forced load has an official warning); the module path changes with the new `KERNEL_DIR` layout (hard-coding `/stand/...` misses samples)
- [[genode]] — **component tree + session + capability + quota**: a service name is valid only at the local parent level (each level can remap, and a label can be rewritten); a capability is a PD-local name; **quota donation is deducted level by level along the path** ("the system still has memory" and "this child OOMs" are not a contradiction); a ROM session supports update
- [[minix3]] — **RS self-healing restart** (a driver disappearing and reappearing is normal); **the label is stable, the endpoint changes**; messages are a fixed 56 bytes, and bulk data goes through **grants** (`EPERM` = the grant is invalid, `EFAULT` = unmapped); **during live update the old and new instances coexist** (it is not injection)
- [[plan9]] — **a per-process namespace** (the same path name can be a different object); **a union is only a single-level overlay**; `/srv` is a service registry, not a socket; **a 9P fid is a handle inside a session**; `open/read/write` is often a user-mode RPC
- [[helenos]] — a **fibril** (a user-mode cooperative scheduling entity; **the kernel does not know it exists**); the **user-mode DDF driver framework** (`driver_ops_t` callbacks; devman matches and starts by match-id score); the business is not in a kernel dispatch table
- [[redox]] — the **scheme model** (`read()` is not necessarily a filesystem; the client fd and the provider descriptor are not equal; a provider often enters the null namespace) + the **boot chain** (bootloader → a tiny ELF-loader bootstrap → a two-stage initfs boot) + **relibc / the auxiliary vector** (the stable ABI is in user mode, and **the syscall ABI is deliberately unstable**) + a driver is a user-mode daemon (initfs and the main system are **built in two passes**)
- [[haiku]] — **driver side**: the device_node tree + on-demand discovery + two layers, driver module/device module; **system side**: the team/thread/area/port/semaphore kernel-object model, **KDL** (stack backtrace/threads/memory/switch CPU) and the debug API (**incompatible** with BeOS), the one-way BeOS R5 compatibility boundary, the user-mode service boundary
- [[zos]] — **TCB and SRB**, **home/primary/secondary**, AR-mode ALET; plus **load module / program object (PDS vs PDSE)**, **AMODE/RMODE**, **XPLINK and non-XPLINK have reversed stack behavior** (direction, a 0x800 bias, the unwind mechanism), the SVC/PC tables, dump types and IPCS (under XPLINK there are fewer control blocks; look at LEDATA), EBCDIC and the record model
- [[ibmi]] — the **layers** (where MI / TIMI / SLIC / PASE meet), the **program model** (OPM/EPM/ILE; `*MOD`/`*PGM`/`*SRVPGM`; bind-by-copy vs by-reference), the **activation group** (PSSA/PASA/heap and override scope), **two kinds of pointer** (system pointer/space pointer) and **two storage models** (single-level vs teraspace, including the job boundary and tagged-pointer limits), **identifying executable material** (DMPOBJ/compile listing/compressed state/timestamps necessarily differ)
- [[openvms]] — **two control flows**: AST (completion order **write the IOSB → set the event flag → deliver the AST**; it does not abort a system call in progress; a wait that was interrupted is executed again) and **condition handling** (continue/resignal/unwind of the handler chain, a second exception skips frames already searched, the default set of three at image startup, differences between languages); also **image activation and shareable images** (logical-name redirection, the limits of a privileged/execute-only image) and the calling standard
- [[unikraft-mirageos]] — **library OS / unikernel**: a single address space, a single protection domain; native (a syscall becomes a function call) vs binary-compatible (trap the syscall of a Linux ELF); **device wiring comes from the build-time configuration**, and the same source behaves completely differently on different targets
- [[hic]] — **capability + physical sandbox + a multi-version driver system**: **processes at the same physical privilege level are isolated by the MMU** (`Ring 0 → the whole kernel is addressable` is an invalid assumption here); **module metadata comes before disassembly**; **the entry-page IPC shape** is not obfuscation; a shared-memory pointer carries domain semantics `{domain, cap, mapping, offset, length, rights}`; **model the driver lifetime and the hardware lifetime separately** (instance/domain/device ownership/DMA/IRQ routing/binding/version/migration state). Includes a cross-system comparison (Fuchsia / seL4-CAmkES / Xen / Genode / QNX / multi-kernel / MINIX) and a **hit / do-not-hit list** (so it is not triggered by mistake on another capability system)

## When to use / when not to use

- Prerequisite: **you are not sure which system the target belongs to** (not PE/ELF, the OSABI points at a non-mainstream system, there is no standard container) → pass [[re-analyze/system-fingerprints]] first
- Use: static reversing and runtime verification of kernel-mode payloads and drivers on each platform (a malicious driver / rootkit / anti-cheat / EDR countermeasure / a closed-source driver)
- Use: recovering the object graph / capability distribution / IPC topology of a **capability system** (seL4 and similar microkernels), and deciding "why the behavior differs from an ordinary OS"
- Use: **Fuchsia/Zircon** — recovering the handle and rights relationship, DFv2 driver bind-rules matching and the driver-host partition, and deciding co-located driver communication ([[zircon-kernel]])
- Use: **FreeBSD / illumos·Solaris** — initialization registered by a linker set (no caller can be found) and the KLD lifetime ([[freebsd-kernel]]); reading the DDI/DKI driver skeleton and `dev_ops`/`cb_ops` capability ([[illumos-kernel]])
- Use: you need to decide "what this code in memory / in the kernel is, where it came from, and whether it was changed"
- Do not use: UEFI / the boot stage (a bootkit) → [[re-uefi]]; RTOS kernel objects → [[re-rtos]]; an eBPF program (the BPF-64 instruction set, progs/maps) → [[re-ebpf]]; TEE / TrustZone → [[re-tee]]; kernel debugging and crash location only → [[re-windbg]] / [[re-lldb]]
- Do not use: you only need to collect a payload from memory (not analyze kernel structure) → [[re-sample-acquire]]

## Tool preparation (by platform; details are in each branch)

- **Windows**: [[re-ghidra]] / [[re-ida]] (import WDK kernel types), [[re-windbg]] (two-machine / KDNET kernel debugging), the Microsoft public symbols; turn test signing on only inside the debug VM (`bcdedit /set testsigning on`, Secure Boot has to be off)

## Common pitfalls (cross-platform)

- **Concluding from the disk version alone**: a Linux init-only section is already gone at runtime, a macOS AuxKC may still be running the old version, and Android may have loaded a same-named module from another partition — **align the three identities "disk / running / loaded collection" first**
- **Treating a legal shape that "looks broken" as corruption**: a Linux signature trailer, a livepatch section, and split BTF are not corruption (see the shape classes in [[linux-kernel]])
- **Explaining an offset or symbol error with a same-version assumption**: RANDSTRUCT, MODVERSIONS, and a KMI branch all make "the same version" actually different
- **Judging "no hook / no hidden module" from a single view**: `lsmod`, the syscall table, or `/sys/module` being clean is not a conclusion by itself — it must be a cross-view, and **when the views contradict, trust offline memory forensics first**
- **Watching only the old few hook techniques**: modern landing sites include an operation structure, ftrace, kprobes, and inline text — "the syscall table was not hooked" does not mean the kernel is clean
- **Kernel-mode operations have no isolation**: loading / triggering kernel code can crash the machine directly (a Windows blue screen); do everything inside a debug VM + a snapshot (the top rule in [[re-sandbox]])
- Platform-specific pitfalls are in the matching branch ([[windows-kernel]] / [[linux-kernel]] / [[macos-kernel]] / [[android-kernel]])
