# Nim binary layout: entry chain / string structures / GC and exception implementation

A Nim build is generated C plus a linked runtime library: the entry chain, string layout, GC, and exception implementation all change with the compiler version and the GC mode. Confirming "version + GC mode" before picking a layout is the premise of the analysis.

## Entry chain (ELF, Linux default C backend)

```
C main
  └─ NimMain          （运行时初始化：GC 启动、堆栈底部设置）
       └─ NimMainInner
            └─ NimMainModule   （各模块初始化：全局变量构造、模块级代码）
                 └─ 业务 main（用户定义的 main 过程）
```

- Symbol shape (measured on nim 2.2.10): `NimMain` / `NimMainInner` / `NimMainModule` are all exported functions; `main` is the C entry
- Module-level function names carry a module prefix and a hash suffix: `main__hello_u8`, `check__hello_u5` (the `<proc>__<module>_<id>` shape)
- Runtime types such as strings exist as C structs in the debug types: `NimStringV2` / `NimStrPayload` (they disappear after strip; recover them from the layout table)

## String structures (split by GC mode)

### orc/arc (2.x defaults to orc; the C structs generated by 2.2.10, measured)

```c
struct NimStringV2 {          /* 8/16 字节（64 位）：len + 指针 */
    NI len;                   /* 字节长度（不含结尾 \0） */
    NimStrPayload* p;         /* 堆上 payload；len==0 时可 nil（字面量 p 指向静态区） */
};
struct NimStrPayload {
    NI cap;                   /* 容量；cap 高位 bit(62) 为 strlitFlag（字面量标记） */
    NIM_CHAR data[];          /* 内联字符数组 */
};
```

- `strlitFlag = 1 shl (sizeof(int)*8 - 2)` (bit 62 on 64-bit): cap carrying this bit means a string literal (static storage, immutable)
- Allocation function: `rawNewString` (this importc name is the same on 1.x and 2.x; measured the same on 1.6 and 2.2)
- Memory picture: `NimStringV2` can be inline on the stack or inside an object; the payload is a separate heap allocation (with a cap prefix)

### refc (the 1.x default and 2.x `--gc:refc`; NimStringDesc)

```c
struct NimStringDesc {        /* len/reserved + 内联字符 */
    NI len;
    NI reserved;              /* 已分配容量（高位带 seqShallowFlag/strlitFlag 标记） */
    NIM_CHAR data[];          /* 内联 */
};
```

- The string body is the struct itself, with no separate payload; `NimString = ptr NimStringDesc`

### Decision table (judge the GC mode, then pick the layout)

| Clue | orc/arc (v2 string) | refc (NimStringDesc) |
|---|---|---|
| Compile default | Nim 2.x default | Nim 1.x default / 2.x explicit `--gc:refc` |
| GC symbols (debug) | `nimIncRefCyclic` `nimDecRefIsLastCyclicDyn` | `nimGC_setStackBottom` `nimGCunref` `nimGCvisit` |
| String allocation | `rawNewString` (2.x) | `rawNewString` (1.x via the `newStringOfCap` importc, same name) |
| String compare | `eqStrings` (both have it, visible in debug) | same as the left |

## GC and ownership

- refc: reference counting plus cycle collection (the nimGC_* family); many explicit inc/dec call sites
- orc/arc: ARC semantics plus cycle collection (`nimIncRefCyclic` / `nimDecRefIsLastCyclicDyn`); retain/release is inserted by the compiler at assignment and scope boundaries, with no explicit counter
- In a release build (`-d:release`) GC helper functions are often inlined away — the symbol table is complete in a debug build; a release build is judged from behavior

## Exception implementation (large version differences)

| Version / switch | Mechanism | Visible symbols |
|---|---|---|
| Nim 2.2.x default (Linux x86-64, orc) | goto-style exception table (`--exceptions:goto`) | no setjmp; `raiseExceptionEx` / `raiseExceptionAux` |
| Old default (`--exceptions:setjmp`, Nim 2.0 and earlier) | setjmp/longjmp | `nimSetjmp` |
| `--exceptions:cpp` | C++ exceptions (C++ backend) | `__cxa_throw` and the rest |

- Measured (2.2.10 orc): the binary has `.eh_frame` but no `.gcc_except_table`, no `__gxx_personality_v0`, and no setjmp — "exception handling is present but setjmp is not visible" is normal on 2.2+
- Locate a catch: from a `raiseExceptionEx` call site, look back at the exception table / branch structure; the exception object has a type field (a Nim exception is a ref object, and the first field is a type pointer)

## Version timeline

- 1.x: default refc + NimStringDesc + setjmp exceptions
- 2.0.x: orc becomes the default GC, and strs_v2 (v2 strings) turns on with orc; `--gc:refc` is still the old layout
- 2.2.x: Linux amd64 defaults to goto-style exceptions (no setjmp symbol); `rawNewString` replaces the `newString1` name
- What carries across versions: locating the entry chain, following string-compare sites, recovering exception paths. What does not: concrete symbol names and structure offsets
