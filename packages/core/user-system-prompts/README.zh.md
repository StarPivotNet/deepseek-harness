# dsh-user-system-prompts

[English](README.md) | 中文

用户编写的系统提示词库，以及按模型组装。`UserSystemPrompts` 提供 `ctx.userSystemPrompts`，并从实时 volatile Config 暴露 `user-system-prompts` settings 命名空间。设置页通过该条目的 settings 命名空间写入提示词库与绑定。

设置页负责创建、编辑、删除，以及按模型多选、排序、覆盖，并替换已注册的插件段。本包在协作式组装之后、以及任何 complete 段还原之后，先应用已存储的段替换，再应用当前模型选中的提示词。

- `ctx.userSystemPrompts.current()` 返回一份独立的 `{ prompts, bindings, overrides }` 快照。
- 一条 `{ name, text }` 覆盖会替换该已注册段的已组装文本。空字符串会隐藏该段。未知名称在组装时被忽略。
- `override: false` 的绑定按列表顺序把选中的提示词追加到已组装段之后。
- `override: true` 的绑定替换这些已组装段。该替换发生在 `complete` persona 还原之后，因此用户覆盖就是模型收到的提示词。
- 已组装的 `{{provider}}`／`{{model}}` 对没有绑定、或选择为空时，选中库这一步保持不变。

未知提示词 id、重复 id、重复覆盖名称以及重复的模型键会在 Settings 写入时失败。组装把已存储列表视为精确列表。

## 模型体验

### 选中的用户提示词

#### 模型所见

当一次请求已组装的提供方与模型匹配某条绑定时，选中的库文本以 `user-system-prompt:<id>` 段按列表顺序出现。追加模式保留此前全部段，并把这些段加在后面。覆盖模式让这些段成为完整的系统提示词。

#### Token 影响

选中文本在该模型的每次请求中重复。覆盖模式会移除这些请求的其余全部系统提示词 token。

#### KV Cache 影响

只要库文本、列表顺序、覆盖开关、已注册段替换以及此前已组装段保持相同，前缀就保持稳定。编辑已选提示词、改顺序、切换覆盖、编辑自带段，或切换会话模型，可能从第一个变化的系统提示词 token 起使复用失效。

## 已知限制与暂缓事项

- 绑定按提供方路由加模型 id 索引，不按会话。每个组装出该对的会话都收到同一选择。
- 随附循环注册 `{{provider}}` 和 `{{model}}`；缺少这些变量的组装无法匹配绑定。
