# Agent Note: 会话控制搜索按剩余结果数限制标题读取

Status: implemented

[English](2026-09-06-session-control-search-bounded-title-reads.md) | 中文

## 问题

非空的会话控制查询在应用结果上限之前，会加载全部符合条件会话的标题。即使只请求一个近期会话身份，也要等待无关历史日志完成读取和解压。因此，较小的结果上限无法避免不必要的标题读取。

## 决策

[会话控制搜索](../../../../packages/session-query/session-control/README.zh.md) 在归档过滤之后，按语料的最新优先顺序读取标题。每批最多包含尚缺的结果数。获得足够匹配后，搜索停止安排标题读取，并在每批读取期间保留取消能力。返回行仍带有最新折叠标题，包括身份或 cwd 命中的行；标题读取失败时仍回退到会话 id。

[查询语料库](../../../../packages/session-query/session-query/README.zh.md) 在既有并发上限内，对每个请求的持久化 id 执行定点 `stat` 和日志读取。各批次不重复列出完整语料库，元数据失败只影响该 id。异步读取后仍优先使用实时挂载的会话。

这减少了读取量，而不改变[可信目录](../feature/2026-08-19-trusted-session-control-directory.zh.md)约定，也不引入独立的标题索引。

## 考虑过的替代方案

**过滤前加载全部标题。** 批量处理较简单，但少量结果请求也要等待无关的冷日志。

**每批重新列出持久化会话。** 这会随着搜索推进反复执行全库元数据操作，即使批次很小也一样；定点观察使这部分工作量与请求的 id 数量相称。

**身份或 cwd 匹配时跳过标题读取。** 这能节省读取，但会改变返回标题，也可能越过更新的纯标题匹配，违反最新优先的匹配语义。

## 影响

查询得到足够匹配行后即停止读取。匹配稀少或没有匹配的查询仍可能扫描全部符合条件的语料，冷标题可能需要读取完整日志。结果上限不是耗时或字节预算。

定向搜索测试覆盖提前停止、跨批次纯标题匹配、归档过滤、最新优先顺序，以及在读取后续行之前取消。目录 API 和面向模型的结果结构保持不变。
